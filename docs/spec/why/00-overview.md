# WHY 总览 —— 迁移动机与新设计哲学速览

> 本文件是 why/ 的「总」入口。旧版动机（为什么做 History）见 `history_legacy_spec/why/`；本目录回答的是**为什么要重做为 UniversalHistory、为什么这样设计**。

## 一句话定位

UniversalHistory 是 History 的**地基重做**：作者在旧版 README 中自述「我虽然实现了一个看起来不错的时间轴，但其机制并非严谨的、标准的。进一步的改进也不过是在一个不稳固的地基上堆叠建筑」。迁移的目的不是推翻功能，而是把功能安置到标准、可扩展、AI 友好的地基上，并兑现旧版拖欠多年的承诺（NLP/LLM 录入、Web 版）。

## 四根支柱

| 支柱 | 决策 | 一句话理由 | 分篇 |
| --- | --- | --- | --- |
| 时间 | JDN 微秒定点整数 + 外推格里高利历 + 天文纪年 | 用标准天文零点取代自定义 TICK，消除 0 年跳变与 BCE 镜像特判 | [01](01-time-system.md) |
| 架构 | chrono / models / adapters / render / ui 五层 + Workspace 信号 | 旧版「编辑后不刷新」的结构性修复；UI/解析/数据互不反向依赖 | [02](02-architecture.md) |
| 操作 | 交互与行为继承旧版 + 定点优化 | 旧版交互是多年使用的沉淀；只修缺陷，不换习惯 | [03](03-legacy-inheritance.md) |
| 未来 | Agent 录入与 Web 为一等目标 | 旧版多年前的 NLP 承诺；「无阻力构造历史知识体系」 | [04](04-agent-and-web.md) |

## 设计哲学速查（来自 docs/core_design.md）

- **时空分离**：严格区分「物理时间流」（绝对）与「历法标签」（相对）；底层只存定点整数 JDN，禁止核心层存 (Y,M,D) 元组。
- **零误差算术**：彻底拒绝浮点；所有加减为整数位移；`to_gregorian` 往返误差 0 微秒是金标准。
- **数学标尺而非历史模拟器**：格里高利历向过去无限外推；历史上的 1582 年空白期在本系统存在，历史语义由 UI 层负责。
- **层级吸附**：刻度必须吸附标准日历单位，禁止 `jdn + 固定微秒` 推进（闰年、大小月长度不一）。
