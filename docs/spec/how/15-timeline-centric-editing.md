# HOW · 时间轴为中心的交互设计（Timeline-Centric Editing）

> 本篇是**新设计规范**，落实用户裁决第 4 条：「旧版是先有编辑器才有时间轴，二者结合非常不好；新版以时间轴为主，在这个界面修改新建等等」。
> 与 [14-event-ownership.md](14-event-ownership.md)（归属设计）配套阅读——归属清晰是时间轴中心交互的前提。

## 1. 旧版的问题（明确废弃的结构）

旧版**先有编辑器、后有查看器**：`HistoryRecordEditor` 是带 depot 浏览器的独立工作台，时间轴是后加的展示窗口。二者结合的不良具体表现：

- 菜单打开的编辑器与时间轴**零联动**（保存后轴不刷新，见 legacy `how/13`）；
- 编辑器承载了文件管理、记录列表浏览、编辑三种职责，时间轴只剩「看」；
- 从时间轴进入编辑的唯一路径是双击索引条，且弹出的编辑器与轴仍是两张皮。

## 2. 设计原则

### T1. 时间轴是唯一主界面

浏览、定位、新建、编辑、删除都**从时间轴上下文发起**；主窗口菜单只提供全局/辅助入口。用户的 mental model 是「我在时间轴上操作历史」，不是「我在文件编辑器里编辑记录」。

### T2. 编辑器是时间轴的从属对话框

- 编辑器只编辑**单个事件**，不携带文件管理、depot 浏览（已实现剥离）；
- 目标 source 由时间轴上下文给定并显示（配合 O2/O3/O4）；
- 保存结果通过 Workspace 信号**立即反映在时间轴上**（已实现——编辑即刷新是 T1 的成立条件）。

### T3. 时间轴上的三条操作路径（当前已实现）

| 路径 | 触发 | 行为 |
| --- | --- | --- |
| **新建** | Thread 右键 → New event | 无 source 先 BindSourceDialog（O4）→ EventEditor → Apply 落盘 + 轴即时刷新 |
| **编辑** | 双击事件条 / 右键 → Edit event | EventEditor 打开该事件 → 写回其自身 source → 轴即时刷新 |
| **删除** | 右键 → Delete event | 确认框 → remove + 落盘 → 轴即时刷新 |

### T4. 菜单入口是辅助而非主路径

- View → Event Editor（Ctrl+E）保留，但无 source 时应**引导绑定/选择文件**，而不是打开一个顶部显示 "No source"、Apply 才被拦截的空编辑器（当前行为，`main_window.py:157-160`——列入改进项）。

### T5. 增强方向（设计预留，按优先级）

1. ~~**位置感知新建**~~ **已实现（2026-09-18，F2）**：Thread 上右键 → New event 时，点击处的轴时间（`TimelineView.time_at_screen`）经 `format_jdn` 预填进编辑器 Time 字段（`preset_time_text`），且计为未保存修改（关闭时提示）；
2. ~~**创建后视图跳转**~~ **已实现（2026-09-18，F3）**：编辑器 `event_saved` 接 `TimelineView.reveal_time`——保存的事件在可视范围外才居中跳转，已在屏内（如位置感知新建的点击处）不动；
3. **非模态/侧边面板编辑器**：编辑时时间轴保持可见可操作，取代模态对话框；
4. **快速录入**：轴上 inline 输入（标题 + 时间）一步成事件，完整字段留给编辑器；
5. **悬停/单击展开详情**（§8.6 既有预留）：单击事件在侧边显示完整正文，减少「为看内容而进编辑器」。

## 3. 当前实现对照

| 原则 | 状态 |
| --- | --- |
| T1 轴为主界面 | ✅ 启动即轴 + 自动加载示例 |
| T2 编辑器从属化 | ✅ 单事件编辑、无文件管理、信号联动 |
| T3 三条操作路径 | ✅ 全部可用（含事件级右键） |
| T4 菜单入口引导 | 🔶 空 source 时仍会打开空编辑器（待改） |
| T5 增强 | ⬜ 全部预留 |

## 4. 验收锚点

- 不打开任何菜单，仅通过时间轴上的右键/双击即可完成 新建→编辑→删除 全流程；
- 每条路径的保存目标文件在操作前可见（配合 O2）；
- 每次保存后时间轴即时反映，无需手动刷新。
